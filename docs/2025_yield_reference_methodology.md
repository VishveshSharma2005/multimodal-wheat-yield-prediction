# 2024-25 Wheat Yield: Ground-Truth Availability and Reference Methodology

**Status: NO official district-level 2024-25 Gujarat wheat APY yield is available in this repository.**

The 2024-25 target is therefore missing (`pending_actual_apy`) throughout, and no
2024-25 accuracy metric is computed anywhere.

> **Update 2026-09-05 — the carry-forward defect described in section 3 has been
> FIXED.** The fallback was removed, the contaminated target was cleared, and the
> affected outputs were regenerated by inference only. No model was retrained.
> Section 3 is retained as the record of what went wrong and how it was corrected.

## 3. RESOLVED defect: a 2023-24 value was labelled as a 2024-25 actual

**This was the single most important research-integrity issue in the repository.
It was fixed on 2026-09-05; the record is kept below.**

### What happened

`src/data/ingest_apy_2025_ground_truth.py` filters the raw APY files for
Gujarat + Wheat + Rabi + district-level + `season_year_start in {2024, 2025}`.
That filter correctly returns **zero** rows. The script then falls into a
"permissive fallback" branch (`if not frames:`) that instead takes *the most
recent district-level row of any year* per district:

```python
alt = alt.sort_values("season_year_start").drop_duplicates(subset=["district"], keep="last")
```

`_write_cases_updates()` then writes that value into every case with
`season_year_start == 2024` and marks it as real:

```python
cases.loc[pred_mask, "yield_kg_ha"] = ...map(district_to_yield)
cases["actual_available"]  = cases["yield_kg_ha"].notna().astype(int)
cases["evaluation_status"] = ... "available" ...
```

### The resulting contamination

| Field | Value |
|---|---|
| Affected rows | 9 (Mehsana, `case_id = GUJ_MEHSANA_2024_2025`, all 9 stages) |
| Value written | **2796.06 kg/ha** |
| What that number really is | Mehsana **2023-24** wheat yield, as transcribed in `data/raw/apy/apy_wheat_trace.csv` |
| Marked as | `actual_available = 1`, `evaluation_status = "available"` |
| Downstream effect | `reports/model_results/prediction_2025_evaluation.md` reported **Mehsana 2025 MAPE = 11.93, RMSE = 348.85, MAE = 333.67, R2 = 0.0** |

Those four numbers were **not valid** — they compared a 2024-25 forecast against a
2023-24 observation. They have been removed from the repository and must not
appear in a thesis, paper, or presentation.

### A second, independent problem with the same number

The hand-transcribed PDF trace and the machine-extracted XLSX table disagree for
Mehsana:

| Agri year | `apy_wheat_trace.csv` (manual, from PDF) | `apy_yield_all_districts.csv` (parsed from XLSX) |
|---|---|---|
| 2021-22 | 3292.80 | 3292.80 |
| 2022-23 | **2783.09** (area 451.93) | **3169.33** (area 668.78) |
| 2023-24 | **2796.06** (area 389.00) | **3255.21** (area 671.46) |

The trace file's 2022-23 and 2023-24 area values (451.93 and 389.00 thousand ha)
break the otherwise stable ~670 thousand ha Mehsana wheat area, which is the
signature of a row misalignment during manual transcription. The modelling
dataset uses the XLSX-derived values (Mehsana 2023-24 = 3255.21), so 2796.06 is
inconsistent with the repository's own validation target as well as being the
wrong year.

**Authoritative APY table: `data/interim/apy_yield_all_districts.csv`.**
`apy_wheat_trace.csv` should be treated as provenance/reference only.

### Correct state

Until the Directorate of Agriculture, Government of Gujarat publishes
district-level 2024-25 wheat APY:

* `yield_kg_ha` for `season_year_start == 2024` must be **null**
* `actual_available` must be **0**
* `evaluation_status` must be **`pending_actual_apy`**
* no 2024-25 MAPE / RMSE / MAE / R2 may be computed

This is now the state of the repository.
`reports/model_results/prediction_2025_evaluation.md` reports "Rows with actual
APY: 0" and "MAPE: N/A", and `reports/summaries/forecast_2024_25.md` documents the
forecast-only status in full. (The older `reports/final_evaluation_2025.md`, which
said the same thing, has been moved to `archive/superseded_reports/`.)

`scripts/smoke_test.py` contains a permanent regression check
(`2024-25 ground-truth integrity`) that fails if any 2024-25 row ever carries a
non-null yield again. It now passes.

### Fix APPLIED — 2026-09-05

Changes to `src/data/ingest_apy_2025_ground_truth.py`:

1. **The `if not frames:` carry-forward fallback was deleted.** When no
   district-level prediction-season row exists, the function now returns an empty
   frame and logs a warning. No proxy or estimated actual is created.
2. **`_write_cases_updates()` now builds its lookup from prediction-season rows
   only** (`season_year_start in PREDICTION_SEASON_START_YEARS`), so a row from
   any other season can never supply the prediction-season target. The assignment
   is unconditional, so a stale value left by an earlier run is cleared rather
   than retained.
3. **`_write_stage_updates()` now refreshes all three stage tables**
   (`stage_features.csv`, `stage_features_with_split.csv`,
   `stage_features_with_cnn.csv`), which previously could drift apart — only
   `_with_split` was updated while the models read `_with_cnn`.
4. **The "re-use the previous output" branch in `main()` was removed**, since it
   re-injected the contaminated file on every subsequent run.
5. **`_is_district_level()` now rejects aggregate district names**
   (`ALL_DISTRICTS`, `STATE`, `TOTAL`, ...) and no longer has its `scope` column
   overwritten with `"district"`, so the state-level 2024-25 Final Advance
   Estimate can never be admitted as a district target.

Verified after the fix:

| Check | Result |
|---|---|
| `cases.csv` 2024-25 rows with a target | **0 of 33** |
| `stage_features*.csv` 2024-25 rows with a target | **0 of 297** (all three tables) |
| 2024-25 `evaluation_status` | `pending_actual_apy` for all 297 |
| Training + validation targets | **1188 / 1188 intact**, unchanged |
| `predicted_yield_kg_ha` | **bit-identical** before and after (max abs diff 0.0) |
| Model artefacts | **25 / 25 byte-identical** — nothing retrained |
| `prediction_2025_evaluation.md` | MAPE / RMSE / MAE / R2 all `N/A` |

## 4. If a 2024-25 reference value is needed for the thesis

No proxy has been created, and none should be created merely to make the results
table look complete. If the project needs a comparison anchor, the defensible
options are, in order of preference:

1. **Wait for the official district release.** This is the only path to a real
   evaluation.
2. **State-level benchmark.** Quote Gujarat 2024-25 state wheat yield =
   **3280.69 kg/ha** (Final Advance Estimates, 24-25 report) and compare it to the
   *state* aggregate of the 33 district forecasts. Label it explicitly as a
   state-level sanity check, never as a Mehsana district evaluation.
3. **Historical reference band.** Report the Mehsana 2020-21 to 2023-24 observed
   range (3169.33 - 3389.73 kg/ha, XLSX source) and say whether the forecast falls
   inside it. This is a plausibility check, not an accuracy metric.

If any such value is ever materialised into a column, it must be named
`state_benchmark_yield_kg_ha`, `reference_2025_yield_kg_ha`, or
`forecast_reference_yield_kg_ha` — **never** `actual_yield_kg_ha` — and must
carry its own `source_year` and `source_scope` columns.

## 5. How to describe this in a thesis / presentation

> Model performance is reported on the 2023-24 validation season (33 districts x
> 9 stages = 297 stage-level observations). The 2024-25 season is presented as a
> forecast only: district-level Area-Production-Yield statistics for Gujarat wheat
> 2024-25 had not been released at the time of writing, so no accuracy metric can
> be computed for that season. The available 2024-25 figure is a state-level Final
> Advance Estimate (3280.69 kg/ha) and is used solely as an aggregate plausibility
> benchmark.

**Do not write** "2025 MAPE = 11.93%" or "actual 2025 Mehsana yield = 2796.06 kg/ha".
